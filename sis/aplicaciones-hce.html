Aplicaciones y historia clínica electrónica

Para registrar y explotar los datos asistenciales se usan aplicaciones informáticas. La historia clínica electrónica (HCE) es su núcleo.

Resumen en 3 líneas

1. Hay aplicaciones estatales (Selene, HCIS, Gacela Care) y autonómicas (Jimena, Diraya, Jara) para registrar datos clínicos.

2. La HCE es una base de datos centrada en el paciente: los datos se añaden, no se borran.

3. Aporta orden y rapidez, pero exige formación, soporte técnico, interoperabilidad y mucha seguridad.

Aplicaciones de registro y explotación #

Una aplicación de este tipo permite registrar los datos clínico-asistenciales y luego explotarlos (consultarlos, sacar listados y estadísticas).

Qué debes quedarte

Basta con reconocer los nombres y saber que unas son de ámbito estatal y otras autonómicas. Ampliación Cada servicio de salud autonómico usa su propia aplicación, por eso la interoperabilidad (más abajo) es tan importante.

La historia clínica electrónica (HCE) #

HCE en una frase

Es la historia clínica en soporte informático: una base de datos relacional centrada en el paciente y organizada por problemas.

Características #

  • Centrada en el paciente #

    Base de datos relacional organizada por problemas de salud.

  • Empieza por lo administrativo #

    Incorpora inicialmente los datos administrativos del paciente.

  • Misma estructura que el papel #

    Sigue las pautas estructurales de la HC en papel.

  • Texto libre firmado #

    Permite anotaciones libres, con nombre, especialidad, fecha y hora del profesional.

  • Peticiones #

    Facilita pedir pruebas (laboratorio, radiología) y registra quién pide y quién consulta.

  • Solo lo reciente o relevante #

    En historias extensas permite ver solo los datos recientes o relevantes.

  • No se borra, se añade #

    Los datos no pueden borrarse, pero sí añadirse.

  • Se «cierra» con el tiempo #

    Pasado cierto tiempo no se puede modificar nada de lo registrado.

  • Mismas normas de conservación #

    Se conserva con las mismas normas que la HC tradicional.

Ejemplo: corregir un error

Un médico anotó «alergia a penicilina» por equivocación. No puede borrar la nota: añade una anotación nueva que la corrige, con su nombre, fecha y hora. Así queda constancia de todo lo ocurrido.

Ventajas y desventajas #

Filtra y abre cada tarjeta. Dentro de cada una hay una idea para sacar partido o mitigar el problema.

Balance de la HCE #

Ventajas y desventajas, con ideas de mejora.

Interoperabilidad Ampliación #

Interoperabilidad es la capacidad de que sistemas distintos se intercambien datos y los entiendan igual.

Caso típico

El laboratorio usa un programa y el hospital, otro. Si no están integrados, alguien debe teclear los resultados a mano: hay demoras y errores. Con interoperabilidad, el resultado llega solo a la historia del paciente.

  1. TécnicaQue los sistemas se conecten y envíen mensajes.
  2. SemánticaQue «diabetes» signifique lo mismo en todos (códigos comunes).
  3. OrganizativaQue haya acuerdos y normas para compartir datos.

Seguridad y trazabilidad Ampliación #

La HCE guarda datos muy sensibles. Para protegerlos se combinan varias medidas:

  • Identificación #

    Cada profesional entra con su usuario y credenciales personales.

  • Perfiles de acceso #

    Cada perfil ve solo lo necesario para su trabajo.

  • Registro de accesos #

    Queda anotado quién consulta o modifica qué y cuándo (trazabilidad).

  • Copias de seguridad #

    Se guardan copias para recuperar los datos si algo falla.

Ejemplo de fallo

Si los permisos están mal configurados, una persona sin relación con el paciente podría abrir su historia. Por eso se revisan los perfiles y se auditan los accesos. Más en Aspectos legales.

Resumen #

  • Aplicaciones estatales: Selene, HCIS, Gacela Care. Autonómicas: Jimena, Diraya (Andalucía), Jara (Extremadura).
  • La HCE es una base de datos relacional centrada en el paciente y organizada por problemas.
  • Los datos no se borran, se añaden; pasado un tiempo no se modifican.
  • Ventajas: orden, legibilidad, acceso simultáneo, explotación de datos. Desventajas: rigidez, tiempo, complejidad, costes, dependencia técnica y desconfianza.
  • Interoperabilidad y seguridad (con trazabilidad) son claves para que funcione bien.
